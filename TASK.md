# Recipe Explorer Practice

Проект для закрепления Vue 3, Composition API и TypeScript. Он повторяет основные задачи из двух предыдущих проектов и добавляет сортировку, цепочку событий между компонентами и сохранение избранного.

## API

- Данные: https://dummyjson.com/recipes?limit=30
- Документация: https://dummyjson.com/docs/recipes
- Нужный массив находится в поле `recipes` ответа.

## Ограничения

- Без Vue Router.
- Без Pinia.
- Без UI-библиотек.
- Без серверного поиска и серверной сортировки.
- Не изменяй исходный массив при фильтрации и сортировке.

## Структура компонентов

- `App.vue` — запрос, состояния, фильтры, сортировка и избранное.
- `src/components/RecipeList.vue` — получает готовый список и передаёт каждый рецепт в карточку.
- `src/components/RecipeCard.vue` — отображает один рецепт и сообщает о нажатии на избранное.
- `src/types/recipe.ts` — типы данных, ответа API, табов и сортировки.

## Этап 1. Получение данных

1. Создай состояния для рецептов, загрузки и ошибки.
2. Получи 30 рецептов через `fetch` и `async/await`.
3. Проверь `response.ok`.
4. Извлеки массив `recipes`.
5. Добавь цепочку состояний:
   - загрузка;
   - ошибка;
   - пустой результат;
   - список.
6. Опиши тип полного ответа API, а не только отдельного рецепта.

## Этап 2. Карточки

Сначала можно вывести карточки прямо в `App.vue`.

Для каждого рецепта покажи:

- изображение;
- название;
- кухню;
- сложность;
- рейтинг;
- время подготовки;
- время приготовления;
- калории на порцию;
- типы приёма пищи.

## Этап 3. Поиск

Добавь локальный поиск по:

- названию;
- кухне;
- тегам.

Требования:

- игнорировать регистр;
- убирать пробелы по краям запроса;
- пустой запрос не должен ограничивать список;
- поле `tags` является массивом, поэтому нужно проверить каждый тег.

## Этап 4. Табы

Сделай динамические табы:

- Все;
- Завтрак;
- Обед;
- Ужин;
- Десерт.

Значения API:

- `Breakfast`;
- `Lunch`;
- `Dinner`;
- `Dessert`.

Поле `mealType` является массивом. Рецепт подходит табу, если массив содержит выбранный тип. Для таба «Все» фильтр по типу блюда отключён.

Поиск и выбранный таб должны работать одновременно.

## Этап 5. Сортировка

Добавь `select` с вариантами:

- без сортировки;
- сначала высокий рейтинг;
- сначала быстрое приготовление;
- сначала меньше калорий.

Для варианта «быстрое приготовление» сравнивай сумму времени подготовки и приготовления.

Сортировка должна:

- применяться после поиска и табов;
- возвращать новый массив;
- не менять исходный массив рецептов.

Можно использовать один итоговый `computed`, который последовательно фильтрует и сортирует данные.

## Этап 6. Разделение на компоненты

После завершения логики:

1. Перенеси список в `RecipeList.vue`.
2. Перенеси одну карточку в `RecipeCard.vue`.
3. `App.vue` передаёт готовый список в `RecipeList`.
4. `RecipeList` передаёт один рецепт в `RecipeCard`.
5. Запросы и фильтрация остаются только в `App.vue`.

## Этап 7. Избранное

Добавь кнопку избранного в каждую карточку.

Состояние избранного хранится в `App.vue` как список идентификаторов рецептов.

Цепочка события:

1. `RecipeCard` сообщает идентификатор выбранного рецепта через `emit`.
2. `RecipeList` принимает событие и передаёт его выше через собственный `emit`.
3. `App.vue` добавляет идентификатор в избранное или удаляет его.

Также передавай вниз информацию, находится ли рецепт в избранном, чтобы кнопка имела активное состояние.

## Этап 8. Фильтр «Только избранные»

Добавь отдельный переключатель.

- Если он выключен, показывай все рецепты, прошедшие остальные фильтры.
- Если включён, оставляй только рецепты, идентификаторы которых находятся в избранном.
- Переключатель должен работать одновременно с поиском, табами и сортировкой.

## Этап 9. Сохранение избранного

Сохраняй список идентификаторов в `localStorage`.

Требования:

1. При запуске приложения восстановить сохранённое значение.
2. При изменении избранного обновлять `localStorage`.
3. Учесть, что сохранённого значения может не быть.
4. Учесть возможность повреждённого JSON, чтобы приложение не падало.

Это упражнение на `watch`, работу с побочным эффектом и безопасный разбор данных.

## Этап 10. TypeScript

Опиши:

- интерфейс рецепта;
- интерфейс ответа API;
- допустимые ключи табов;
- допустимые варианты сортировки;
- props обоих дочерних компонентов;
- события обоих дочерних компонентов.

Не используй `any`.

## Этап 11. Минимальные тесты

Замени стартовый тест шаблона.

Проверь хотя бы:

1. отображение состояния загрузки;
2. отображение пустого результата;
3. отправку события избранного из `RecipeCard`.

## Критерии готовности

- Запрос выполняется один раз.
- Loading, error и empty-состояния работают.
- Поиск работает по трём полям.
- Поиск и табы объединены через логическое «И».
- Табы создаются из одной структуры данных.
- Сортировка не мутирует исходный массив.
- Компоненты получают данные через props.
- Событие избранного проходит через два уровня компонентов.
- Избранное переживает перезагрузку страницы.
- Все состояния и события типизированы.
- Type-check, линтеры, тесты и production-сборка проходят.

3. поиск;
4. табы;
5. сортировка;
6. компоненты;
7. избранное;
8. `localStorage`;
